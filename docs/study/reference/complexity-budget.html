알고리즘 학습 레퍼런스 · C

이 풀이가 시간 안에 들어갈까?

복잡도를 세는 방법과, 코드를 쓰기 전에 제약 조건만 보고 판단하는 방법.

복잡도가 재는 것

복잡도는 “몇 초 걸리나”가 아니다. 입력이 커질 때 연산 횟수가 어떤 비율로 늘어나는가다. 컴퓨터 성능이나 언어에 상관없이 알고리즘 자체를 비교하려고 만든 척도다.

그래서 상수는 버린다. 연산이 3NM + 100번이면 O(NM)이라고 쓴다. N이 커지면 3배나 +100은 의미가 없어지고 “NM에 비례한다”는 성질만 남는다.

핵심

복잡도는 비교를 위한 도구이자, 코드를 쓰기 전에 이 접근이 통할지 판단하는 도구다. 두 번째 용도가 실전에서 더 중요하다.

시간복잡도 계산 3단계

  1. 입력 크기를 변수로 정한다

    문제가 주는 값이다. 격자면 N행 M열, 배열이면 길이 N, 그래프면 정점 V와 간선 E.

  2. 가장 많이 반복되는 “일 한 덩어리”를 찾는다

    보통 가장 안쪽 루프의 몸통이다. 그 안의 작업이 입력 크기와 무관하게 고정된 횟수라면 상수 시간으로 묶어서 1로 센다.

  3. 그게 몇 번 실행되는지 입력 크기의 식으로 쓴다

    그리고 상수와 낮은 차수를 버린다. 2NM + 3N + 7 → O(NM).

구조별로 세는 법

코드 구조세는 방법결과
루프 하나 반복 횟수 그대로 O(N)
중첩 루프 곱한다 — 바깥 N바퀴 × 안쪽 M바퀴 O(NM)
루프 두 개가 나란히 더한다. 그리고 큰 쪽만 남긴다 O(N+M) → O(max)
매 바퀴 절반으로 줄어듦 몇 번 반으로 나누면 1이 되나 = log₂N O(log N)
루프 안에서 이분탐색 곱한다 — N × log N O(N log N)
BFS / DFS 각 정점이 큐에 최대 1회 → 정점 수 + 간선 수 O(V+E)
재귀 호출 횟수 × 호출 1회당 작업 경우에 따라
함정

BFS의 O(V+E)는 넣을 때 방문 표시를 해야 성립한다. 꺼낼 때 표시하면 같은 정점이 여러 번 큐에 들어가 이 상한이 깨진다. 방문 표시 시점은 정확성 문제만이 아니라 복잡도를 보장하는 장치다.

공간복잡도 계산

훨씬 단순하다. 잡아놓은 메모리를 센다. 배열 크기 × 원소 크기를 더하면 끝이다.

C 타입크기10,000개일 때
char1 B10 KB
int4 B40 KB
long long / 포인터8 B80 KB
struct { int r, c; }8 B80 KB

재귀를 쓰면 호출 스택도 공간이다. 깊이 D까지 들어가면 O(D). DFS로 100×100 격자를 전부 훑으면 최악의 경우 깊이가 10,000이 되어 스택 오버플로 위험이 있다 — 같은 문제를 BFS로 풀면 스택을 안 쓰는 이유다.

기준

백준 메모리 제한은 보통 256 MB. 코테 수준 배열은 대개 수백 KB라 시간복잡도가 병목이고 공간은 거의 문제되지 않는다. 단, int arr[10000][10000]은 400 MB로 즉시 초과다.

워크스루: 백준 2178 미로 탐색

N×M 격자에서 BFS로 최단 거리를 구하는 풀이에 3단계를 적용한다.

// 1단계: 입력 크기 = N행 M열
while (!is_empty()) {              // 3단계: 몇 바퀴?
    Point cur = pop();
    for (int dir = 0; dir < 4; dir++) {   // 항상 4바퀴 (상수)
        // 2단계: 범위 체크·벽 체크·dist 설정·push
        //        모두 상수 시간 → 한 덩어리로 1
    }
}

for는 4바퀴로 고정이고 안쪽은 상수 시간이다. 그러니 핵심 질문은 while이 몇 바퀴 도는가 하나로 좁혀진다. 넣을 때 방문 표시를 하므로 각 칸은 큐에 최대 한 번만 들어간다.

while 바퀴 수 ≤ N × M (칸 수) 바퀴당 작업 = 4 (상수) ───────────────────────────────── 총 연산 ≈ 4 × N × M → O(N × M)

공간은 maze 40 KB + dist 40 KB + queue 80 KB = 160 KB, 역시 O(N × M). N=M=100 최악의 경우 연산은 40,000번 — 1억의 0.04%로 압도적 여유.

풀기 전에 감각 잡기

문제가 N ≤ 100 같은 제약을 주는 이유는 어느 복잡도까지 허용되는지 알려주는 것이다. 제약을 먼저 읽고 목표 복잡도를 정한 다음 접근을 고르면, 통하지 않을 풀이에 시간을 쓰지 않는다.

기준선

1초에 약 1억(108) 연산. C는 실제로 이보다 빠르지만 안전하게 잡는 값이다. 시간 제한이 2초면 2억까지.

제약허용 복잡도연산 수대표 접근
N ≤ 10 O(N!) 3.6 × 10⁶ 순열 완전탐색, 백트래킹 여유
N ≤ 20 O(2N) 1.0 × 10⁶ 부분집합 완전탐색, 비트마스크 여유
N ≤ 500 O(N³) 1.25 × 10⁸ 플로이드–워셜, 3중 루프 DP 경계
N ≤ 5,000 O(N²) 2.5 × 10⁷ 2중 루프 DP, 인접 행렬 여유
N ≤ 200,000 O(N log N) 3.5 × 10⁶ 정렬, 이분탐색, 우선순위 큐 여유
N ≤ 10,000,000 O(N) 1.0 × 10⁷ 한 번 훑기, 투 포인터, 누적합 여유
신호

N ≤ 100,000인 문제에서 O(N²) 풀이를 떠올렸다면 100억 연산 — 코드를 쓰기 전에 이미 시간 초과다. 구현하지 말고 다른 접근을 찾으라는 신호로 읽어야 한다.

문제 풀기 전 체크리스트

  • 제약 조건(N의 상한)을 먼저 읽었다
  • 위 사다리표에서 목표 복잡도를 정했다
  • 떠올린 접근의 복잡도가 그 목표 안에 든다
  • 최악의 경우 연산 수를 실제로 계산해봤다
  • 배열 크기를 제약의 상한으로 잡았다 (넉넉하게 +1)
  • 재귀를 쓸 경우 최대 깊이를 확인했다
