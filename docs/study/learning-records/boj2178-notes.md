## 테스트 케이스

| 파일 | 입력 | 기대 | 결과 |
|---|---|---|---|

실행: `./solution.exe < input-4x6.txt`

## 개념 확인 (완료)

- **왜 BFS인가**: BFS는 거리 순서로 퍼지므로 도착칸에 처음 닿은 순간이 최단. DFS는 첫 도달이 최단이라는 보장이 없어, 최단을 구하려면 모든 경로를 탐색해야 함(격자에서 경로 수가 지수적으로 폭발). → 정답
- **방문 표시 시점**: 처음엔 "꺼낼 때"라고 답했으나, 3×3 격자 손추적으로 중복 삽입을 스스로 발견하고 "넣을 때"로 수정. 넣을 때 표시하면 각 칸이 큐에 최대 1회만 들어가므로 큐 배열 크기 상한이 `N*M`으로 확정됨.

## 큐 구현 (완료)

전역 값 배열 + head/tail 인덱스 방식. `malloc` 없이, 원형 큐 없이.

```
Point queue[MAX_N * MAX_N];  // 값 배열
int head = 0, tail = 0;      // tail=다음 넣을 자리, head=다음 꺼낼 자리
push: queue[tail++] = new_point;
pop:  return queue[head++];
is_empty: return head == tail;
```

- 원형 큐가 불필요한 이유: 각 칸이 최대 1회 삽입 → 전체 push 횟수 ≤ 10,000. 배열을 그만큼 잡으면 인덱스를 앞으로만 밀어도 넘치지 않음.
- 테스트 통과: `(1,1) (1,3) (2,4)` 삽입 → 같은 순서로 pop 확인 (FIFO)

## 막혔던 지점 (C 전환 병목)

1. **pass-by-value** — `push(Point** que, int head, int tail, ...)`로 시작. C에서 int를 넘기면 복사본이라 함수 내 `tail++`이 호출자에 반영되지 않음. Python `deque`는 객체가 상태를 갖고 있어 겪지 않던 문제. → 전역 변수로 해결
2. **선언 순서** — 전역을 `push` 위로 옮겼으나 `typedef` 위로도 넘어가서 `unknown type name 'Point'`. C는 위에서 아래로 한 번 읽으므로 "쓰기 전에 선언" 규칙. 2회 반복해서 물림
3. **`Point*` vs `Point`** — malloc 방식을 버렸는데 배열 타입이 포인터 배열로 남아 타입 불일치
4. **`while (is_empty())`** — `!` 누락. 컴파일·실행 모두 성공하고 조용히 아무 일도 안 함

## BFS 본체에서 막혔던 지점

5. **연쇄 비교 `0 <= nr < N`** — C에 없는 문법. `(0 <= nr) < N`으로 해석되어 0/1과 N을 비교하므로 N≥2면 **항상 참** → 범위 체크가 완전히 무력화. 배열 밖 접근으로 이어짐. `gcc -Wall`이 경고로 잡아준다 (`comparisons like 'X<=Y<=Z' do not have their mathematical meaning`). Python 연쇄 비교 습관의 직접 전이
6. **`N`, `M`을 `main` 지역 변수로 선언** — 스코프 문제 재발(head/tail에서 한 번 겪은 것). 코테에서는 N, M, 격자, 큐 모두 전역이 기본
7. **pop 직후 `if (dist[cur.r][cur.c] == -1)`** — "꺼낼 때 방문 표시" 설계의 잔재. 넣을 때 표시하면 꺼낸 칸은 항상 방문 상태이므로 이 조건은 항상 거짓 → BFS가 첫 바퀴에 종료. **방침을 바꿨는데 옛 방침의 코드가 남아 조용히 망가진 사례.** 방문 검사는 push 직전 이웃에 대해 한 곳만 있으면 됨
8. **`dist` 설정 누락** — `push`만 하고 거리를 안 정하면 방문 표시가 안 되어 같은 칸이 무한 재삽입. `dist[nr][nc] = dist[cur][cur]+1; push(nr,nc);` 두 줄은 항상 붙어다니는 한 동작
9. **실행 방법 착오** — 프로그램 실행 후 `.\test < input.txt`를 따로 입력. `<`는 셸 지시라 실행과 같은 줄에 있어야 함. scanf 실패로 N=M=0 → `dist[-1][-1]` 배열 밖 접근 → 우연히 0 출력

## 엣지 케이스

1×1 미로의 답은 **1** (시작칸도 세므로). `dist[0][0] = 1`로 초기화한 덕에 자동 통과 — 0으로 초기화했다면 오답이었을 케이스.
