# 학습자의 기존 자산을 먼저 조사해야 계획이 성립한다

## 관찰

`algo-study` 임시 워크스페이스에서 두 세션을 진행하고 5단계 커리큘럼을 세웠다. 그 후 사용자가 "바탕화면의 Study/Algorithm에 접근할 수 있나"라고 물어 발견한 것:

- **`solutions/python/` 121개 풀이** — search 38, implementation 24, brute-force 13, greedy 12, graph 8, divide-and-conquer 7, dynamic-programming 6, string 6, data-structures 3, bit 2, math 1
- **`solutions/c/` 19개 풀이** — array, data-structures/linked-list, math, misc, search, simulation, string
- 확립된 저장소 구조, `CMakeLists.txt`(CLion 타겟), README의 명명·커밋 컨벤션, 마이그레이션 계획 문서

**초안 계획의 1·2단계 문제 목록이 거의 전부 이미 Python으로 풀려 있었다.** 2178, 2667, 1697, 7576, 1926 전부. 게다가 훨씬 어려운 것들도 있다 — 2206/14442 벽 부수고 이동(상태 차원), 13549(0-1 BFS), 13913(경로 복원), 1600, 7569, 2573, 2146.

또한 **연결 리스트를 "누락된 1.5단계"로 추가했는데, C로 이미 구현되어 있었다** (`linked_list.c`, `double_linked_list.c`). [[0002-coding-test-bias-in-curriculum]]에서 "빠진 주제"를 고민했지만, 정작 **빠지지 않은 것을 빠졌다고 판단**한 셈이다.

## 결론

**세션 시작 시 워크스페이스의 기존 자산을 조사하는 것이 미션 인터뷰만큼 중요하다.** 사용자에게 "무엇을 아는지" 묻는 것으로는 부족하다 — 본인도 자기가 뭘 풀었는지 목록으로 기억하지 못한다. 파일이 증거다.

계획을 다시 세운 핵심 전환: **신규 문제 탐색 → 이미 Python으로 푼 문제의 C 재구현.**
- 알고리즘 재고민이 불필요해져 C 구현에 집중된다
- 막히면 **본인이 쓴** Python 코드와 대조할 수 있다 (남의 해설보다 우월)
- 정답을 알고 있어 검증이 쉽다
- 난이도를 크게 올릴 수 있다 (2606 바이러스 수준은 부적절)

## 향후 세션에 주는 함의

- **스킬의 세션 시작 절차에 "solutions/ 와 git log를 확인하라"를 명시했다.** SKILL.md 반영 완료
- 저장소 고유 컨벤션(경로, 파일명, CMake 등록, 커밋 형식)을 스킬에 박아두었다. 새 규칙을 발명하지 말 것
- **검증 필요**: 정답을 아는 상태의 재구현이 오히려 사고를 건너뛰게 만들 수 있다. 1단계에서 효과를 관찰하고, 그렇다면 신규 문제와 섞는다
- 개발 환경은 CLion + CMake. `algo-study`의 VS Code 설정은 이전하지 않았다
- `algo-study` 워크스페이스는 이 저장소로 흡수되어 폐기. 삭제하지 않고 남겨둠
