# 계획을 코테 관점에만 맞추면 미션의 절반이 빠진다

## 관찰

초안 계획(`PLAN.md`)에서 **연결 리스트를 누락**했다. 사용자가 직접 "linked 리스트 이런거는 없나?"라고 물어 발견.

누락 사유는 "코테에 직접 나오는 일이 드물다"였는데, 이는 미션의 절반만 본 판단이다. 미션에는 **"CS 기초 지식을 다지기 위한 자료구조 공부"** 가 명시되어 있다.

## 더 심각한 문제: 순서 오류

단순 누락이 아니라 **선행 조건 오류**였다. 계획에 이미 들어있던 항목들:
- 3단계 "트리의 포인터 노드 표현"
- 4단계 "인접 리스트"

둘 다 연결 구조다. 연결 리스트를 건너뛰면 그 지점에서 반드시 막힌다.

## 결론

**1.5단계로 연결 리스트를 삽입**했다. 위치 근거:
1. 포인터가 현재 병목([[0001-python-to-c-state-handling]])이고, 연결 리스트는 포인터를 배우는 정석 교재다
2. 3·4단계의 선행 조건
3. 1단계에서 "크기 상한을 알면 malloc 대신 정적 배열"을 가르쳤으므로, **malloc이 정답인 경우**와 짝지어야 판단 기준이 완성된다. 한쪽만 가르치면 "malloc은 나쁘다"는 잘못된 규칙으로 굳는다

## 향후 세션에 주는 함의

- 계획을 세울 때 **미션 문서를 두 축(코테 / CS 기초)으로 나눠 각각 점검**할 것. 코테 축이 구체적이라 계획을 잡아끄는 경향이 있다
- 코테 빈도가 낮아도 기초로서 중요한 주제를 체크: 연결 리스트 ✅ 추가 / 그 외 후보 — 비트 연산, 문자열 알고리즘(KMP), 유니온 파인드, 시간·공간 트레이드오프 일반론
- **사용자의 질문이 계획의 검증 장치로 작동했다.** 계획을 제시할 때 "빠진 게 있는지" 명시적으로 물어보는 것이 유효
