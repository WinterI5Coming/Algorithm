## 복잡도

**시간 O(N²), 공간 O(N²).** N=25 → 약 3,000 연산.

핵심: "모든 칸에서 BFS를 돌리면 곱셈이 되어 비싸지 않나?" → **아니다.** `visited` 덕분에 각 칸은 전체 과정에서 한 번만 BFS에 방문되므로, **모든 BFS 호출의 작업량 합계가 N²로 묶인다.** 바깥 이중 루프 N² + 전체 BFS 작업 N²×4 = O(N²).

처음에 `log(N*N)?`이라고 추측했으나 `log`는 **매 단계 절반으로 줄어드는** 구조(이분탐색, 힙)에서만 나온다. 이 문제엔 그런 구조가 없다.

## 막혔던 지점

1. **BFS 본체에 `pop()`이 없음 → 무한 루프.** `push`만 하니 `tail`은 늘고 `head`는 0에 고정되어 `head == tail`이 영원히 성립하지 않았다. 사용자가 무한 루프임을 스스로 진단함
2. **이웃을 시작점에서 계산.** `nr = r + dr[d]`로 함수 인자(시작점)를 계속 사용 → 매 바퀴 같은 칸의 이웃만 봄. `cur = pop()` 후 `cur.r + dr[d]`여야 함. ①과 ②는 같은 뿌리(pop의 부재)
3. **`head`/`tail` 리셋 누락.** 2178에는 없던 새 문제 — BFS를 한 번만 불렀으므로. 전역 상태가 호출 간에 남는다. **아까 논의한 "전역변수의 단점"이 실제로 나타난 지점.** 구조체 방식이면 `q_init(&q)`로 매번 새로 만들어 이 실수가 불가능 ([[0003-globals-vs-struct-encapsulation]])
4. **배열 크기 두 곳이 작음.** `que[MAX_N]` → `que[MAX_N*MAX_N]`, `complexes[MAX_N]` → 넉넉히. 체커보드 배치면 단지가 300개 넘게 나옴
5. **`complex_cnt++` 누락** — 항상 0번 인덱스에 덮어쓰고 개수도 0
6. **`scanf("%s", &buf[i])`** — `buf`여야 함. `&buf[i]`는 i번째 위치부터 쓰라는 뜻이라 줄마다 데이터가 어긋남
7. **`buf[j] - '0'` 누락** — 문자 코드 48/49가 들어가 `grid == 1`이 영원히 거짓
8. **출력 형식** — `printf("%d ")`로 한 줄에 이어붙임. 문제는 한 줄에 하나씩

2178 대비 개선: 연쇄 비교(`0 <= nr && nr < N`)를 처음부터 올바르게 작성. 전역 선언 순서도 정확. `qsort` 비교 함수도 스스로 정확히 작성.
